Read-only research on 2026-10-09; no hosted/database/device verification.

## Canonical inclusion

**Decision**: Use private._history_completed_participants from 20260928163507_preserve_in_game_leavers.sql, backed by completed sessions. Registered account_id is identity, current_drink_total preserves departures, and pre-start departures are excluded. participants has unique (session_id, account_id) in 004_create_participants.sql.
**Rationale**: Personal historyRepository merges local and early_leave_results; social totals must not use that dataset. early_leave_results exists only until completion.
**Alternatives**: Name aggregation, departure union and client totals rejected for identity/double-counting/privacy.

## Online versus imported

**Decision**: An eligible session must have completed state, non-null started_at/completed_at, and join_code matching ^[0-9]{6}$, and must have neither a gameplay event with idempotency_key starting legacy-import: or payload.imported=true nor a match with source_provider=legacy_import. Both online creation paths (029_host_create_room.sql:48 and 032_room_membership_rpcs.sql:214) generate six-digit codes; both historical import definitions (023_legacy_history_import_schema.sql:464 and 025_session_ownership_roles.sql:1379) generate IMP- codes. Import session_created events independently record legacy-import:session-created and imported=true (025:1498), including zero-match games. This resolves canonical source-code provenance. Preflight must report conflicting markers or completed records outside these known origin forms and stop for explicit handling; never silently classify unknown manual/legacy records. No name matching or new origin backfill is needed.
**Rationale**: 20261001172204_retire_history_import.sql retained canonical imported history despite deleting importer/ledger. No importer restoration or identity backfill.
**Alternatives**: Counting every completed cloud session violates online-only scope.

## Authorization

**Decision**: Reuse private.social_actor(), private.are_accounts_friends and bilateral private.social_blocked from 20261001170905_social_authority.sql. Private definer reads/public invoker wrappers; explicit EXECUTE and qualified search paths. Preserve private.can_access_session and existing compare_registered_players participation scope.
**Rationale**: Friend global totals require a narrow privileged read, not relaxed game policies.
**Alternatives**: Public definer endpoint, Java CRUD, broad RLS or client-side filtering rejected.

## UI/cache/pagination

**Decision**: One ID route, current tabs, contextual actions, account/display generation fence. Batch co-player context; use bounded keyset shared-game and timeline pages, complete SQL aggregates independent of pages.
**Rationale**: Existing lib/queryClient.ts isolates accounts but freshness defaults alone cannot hide cached friend payload during a mandatory permission check. Existing identities and UI can be reused.
**Alternatives**: Social feed/new tab, persistent private cache, N+1 person queries, page-derived totals and background polling rejected.
